# What shipped: week of 24 August 2026

This is the comprehensive weekly shipping note for the changes that reached
`main` from Monday 24 August through Friday 28 August 2026.

## Scope

- **Baseline:** `b59538a` — the last `origin/main` commit before Monday.
- **Endpoint:** `8bd76b2` — `origin/main` at the end of the audit.
- **Change volume:** 262 commits, including merged feature branches, fixes,
  tests, documentation, CI, and dependency updates.

Some feature commits were authored before Monday and merged during this
window. They are included: this note answers what became available on `main`,
not only what was first authored this week. Pure test, lint, merge, and
formatting commits are represented in the quality sections instead of being
listed one by one.

## The short version

whip was renamed, made distributable through GitHub Releases, and gained a
large amount of capability in one week: MCP and LSP integration; direct
browser and macOS computer control; an ACP editor-agent mode; richer
subagents; time travel, forks, workspace rewind, memory, plans, and schedules;
provider catalog/auth improvements; and a much more observable terminal UI.

## Agent workflow and context management

- **Parallel tool execution is now safe by default.** Independent calls run
  concurrently; writes and edits to the same canonical path serialize, while
  unrelated files continue in parallel. Bash remains globally serialized
  because its side effects cannot be attributed to a path.
- **`todowrite` adds persistent, conversation-scoped plans.** It keeps a
  bounded checklist with one in-progress item, reinjects it on each turn, and
  survives compaction and resume.
- **Goals got more practical.** `/goal-from-context [n]` turns the recent
  conversation into an explicit outcome and completion checklist, then starts
  the goal loop. The goal-loop termination condition was fixed so completed
  goals do not continue indefinitely.
- **Long conversations are more durable.** Compaction is now a recorded event
  rather than destructive history deletion; `/compact log` can inspect it and
  `/compact retry` can redo the latest compaction. Proactive compaction uses a
  configurable percentage of the actual provider context window, and a
  provider context-limit rejection triggers one safe retry after compaction.
- **Context decay reduces prompt cost without losing recent work.** Older tool
  output is replaced with informative placeholders once it leaves the hot
  window; superseded reads decay first, and repeated reads of unchanged file
  regions are deduplicated. The later fixes strengthened the hot-window
  invariant and made placeholders explain their age and spilled-output paths.
- **Provider prefix caching is enabled.** Requests carry a stable per-session
  `prompt_cache_key`, with subagent-specific keys so concurrent subagents do
  not collide. This lets compatible providers reuse an unchanged conversation
  prefix between turns.
- **Transient provider failures retry intelligently.** 429s, 5xx responses,
  and transport failures retry with bounded exponential backoff; a stream is
  never replayed after visible text has already arrived.
- **Bash is no longer opaque.** The TUI streams the recent output of a running
  command. If output is truncated, the full 0600 log is spilled to a temporary
  file and its path is given to the model.
- **Interrupted sessions are safer to resume.** Dangling tool calls receive
  synthesized error results so a restarted conversation cannot contain an
  API-invalid call/result sequence.
- **Persistent memory and standing instructions landed.** `remember` and
  `forget` use human-editable Markdown memory files at installation and session
  scope; `/memory` exposes them. User-editable `me.md`, including the `/me`
  editor, provides durable operating rules in the system prompt.
- **The agent can now consult whip's own documentation when asked to configure
  or extend whip.** The system prompt points it at the docs tree instead of
  leaving configuration guidance to guesswork.

## Subagents and autonomous work

- **Subagents became a first-class workflow.** The `subagent` tool supports
  foreground parallel fan-out as well as background work. Foreground reports
  are capped before entering the parent context; task rows use the task
  description and number parallel batches rather than dumping opaque JSON.
- **Background subagents persist and are visible.** `/subagents` (alias
  `/tasks`) shows status and reports, and a dock below the input exposes active
  work. Finished tasks have a grace period, and restored historical tasks stay
  inspectable without cluttering the live dock.
- **Humans can start and direct subagents.**
  `/subagent [-m model[@provider]] <prompt>` works even while a turn is
  running. The task pane
  lets users steer a running task or run follow-up turns against a completed
  task's retained context; the model also has `subagent_steer`.
- **Subagent routing is configurable.** Tasks use a cheap default model by
  default, can be set through `taskModel`/`taskProvider`, and can be overridden
  per tool call.
- **Background editing can be isolated.** `worktreeSubagents` and the
  per-call `worktree` option put background subagents in their own Git
  worktrees when possible, preventing simultaneous agents from scrambling the
  main checkout.
- **Scheduled work arrived.** `/schedule @every …` and `/schedule @at …`
  create persisted, grid-anchored wakeups. A busy agent defers a scheduled
  turn without losing the schedule's cadence.

## Sessions, recovery, and artifacts

- **Conversation time travel is available.** Press escape twice while idle to
  open a rewind picker that live-scrolls the transcript. Rewind restores the
  selected prompt to the input, preserves tool-call/result integrity, and
  supports in-memory forward travel until a new message is submitted.
- **Sessions can fork and be renamed.** `/fork [name]` copies a conversation
  into a new session; `f` in the rewind picker forks from the selected point.
  `/rename [title]` retitles the active session. A fork can be made during a
  turn, with the switch happening safely when that turn finishes.
- **Workspace rewind accompanies conversation rewind.** whip snapshots the
  working tree before a turn and can restore tracked files for a rewind while
  leaving untracked files alone. The rollback is recorded in the session.
- **Session metadata is much richer.** Stored messages now include model,
  usage, tool timing, forks, tags, pins, and timestamps. Resume restores token
  accounting and authored-message history correctly.
- **`/export [path]` writes a transcript as Markdown.** It defaults to a
  session-named file in the current directory and reports the absolute path.
- **`/clear` correctly resets session usage**, and compaction itself is now
  represented in the durable log instead of erasing the raw conversation.

## Browser and computer use

- **`browser_exec` is a native Go browser subsystem.** It can attach to a
  debuggable Chromium session with real cookies, launch a whip-owned dedicated
  browser, use headless mode, or select modes by named session. It offers a
  compact helper language for navigation, DOM/JS work, clicks, typing,
  screenshots, tabs, waits, uploads, dialogs, and accessibility-tree-driven
  interactions.
- **Live browser use has a robust fallback.** If no debuggable real browser is
  found, whip launches a dedicated Chrome instance rather than failing the
  tool call. It also avoids profile collisions, detects poisoned launch
  profiles, and can switch browser driver with ctrl+p.
- **Default-profile Chrome can be driven through an extension relay.**
  `whip browser install` writes an unpacked MV3 extension and a
  token-authenticated loopback relay. After the user explicitly pins a tab,
  whip can control the tab even where direct CDP access to Chrome's default
  profile is blocked.
- **Browser safety is built in.** Metadata hosts are always blocked; private
  addresses are blocked for dedicated/headless mode unless explicitly allowed;
  navigation is rechecked after page actions. Vision-capable models receive
  screenshots as multimodal turn content.
- **`computer_exec` adds macOS computer use.** Its zero-setup path controls an
  already-open Chrome via AppleScript: inspect tabs, navigate, create/activate
  or close tabs, go back/reload, find text, and run JavaScript when Chrome's
  Apple Events option is enabled. The wider macOS helper provides an
  accessibility-tree-first foundation with screenshot/pixel fallback.
- **Computer access has explicit policy controls.** The default is allow-all
  with user blocklists; `computer.deny`, `computer.allow`, `defaultDeny`, and
  `/computer-use` let users choose a stricter posture. Navigation still passes
  the browser URL safety checks, and login walls require the agent to stop and
  ask.

## MCP, skills, and code intelligence

- **whip is now an MCP client and server.** It loads stdio and streamable HTTP
  servers from project `.mcp.json`, global Codex config, and native whip
  config; `whip mcp serve` exposes whip's read/bash/edit/write tools to other
  clients.
- **MCP configuration and management are complete.**
  `whip mcp list|add|remove|import|test` and `/mcp` cover discovery, status,
  reconnection, enable/disable, dry-run import, and CI-friendly diagnostics.
  Whip config wins name conflicts. Server source labels and source-file names
  make failures understandable.
- **MCP behaves well under failure.** Startup is non-blocking, calls to
  failed/disabled servers fail fast, dropped connections reconnect with
  backoff, server instructions enter the system prompt, unknown tool names
  receive a suggestion, and tool output is safely normalized and capped.
- **Import control protects shared configuration.** `mcpImport` can enable,
  allowlist, or exclude Claude/Codex imports; excluded entries remain visible
  as blocked instead of silently being loaded or disappearing. Global
  `~/.claude.json` import and `${VAR:-default}` expansion were added too.
- **Skills comply with the Agent Skills specification.** Names and descriptions
  are validated, model-disabled skills stay manually invocable, and malformed
  skills raise visible warnings. `/context-doctor` estimates the token cost of
  the full injected context, identifies skill sources, and points to likely
  savings.
- **LSP diagnostics now feed directly back to the model.** After `write` or
  `edit`, gopls diagnostics (plus errors in nearby files) are appended to the
  tool result. The stdio LSP manager supports user-configured servers, starts
  lazily, has a short cancellation-aware wait, remembers broken spawns, and is
  visible through `/lsp`.

## Models, providers, authentication, and cost

- **Model discovery comes from providers.** A cached 24-hour `GET /models`
  catalog exposes models without per-model config, including context limits,
  vision, effort, pricing, and output limits. An unknown model at startup
  triggers one catalog refresh and retry before failing.
- **Switching models is smoother.** The picker now type-filters and fuzzy
  resolves input; `/model-for-session` changes the active session without
  overwriting the saved default. Default reasoning effort is model-aware and
  defaults to low where supported.
- **Per-model sampling controls are supported.** `samplingParams` accepts
  `temperature` and `top_p`, sending them only when configured.
- **OpenRouter onboarding is one command.** `whip auth openrouter` and
  `/auth openrouter` validate the key before writing, offer environment-based
  storage, seed the catalog immediately, and mask in-session key entry.
- **Inference.net is now first-class.** `whip auth inference-net login` uses a
  device flow, offers an interactive team/project selection, mints and stores a
  machine key securely, supports BYOK, key rotation, status, and logout, and
  transparently migrates older `inference` configuration to `inference-net`.
- **Token and cost visibility is much better.** The status line shows session
  spend when pricing is advertised, last-response token counts, and context
  size; the rewind picker shows per-turn tokens, cost, and context. Long paths
  no longer hide spend.

## Terminal experience

- **Tool activity is easier to follow.** Tool calls render while arguments
  stream, completed rows use descriptive Claude-style `Verb(subject)` headers,
  write/edit rows show colored, line-numbered diffs, and queued calls update in
  place rather than producing row spam.
- **Transcript rendering improved.** Markdown tables are tighter, URLs and
  existing local file references become OSC 8 hyperlinks, interrupted calls
  are surfaced, and rendering no longer leaks styles on unknown backgrounds.
- **Mouse selection works better.** Selection keeps blank lines, auto-scrolls
  at the viewport edge, maps rows correctly, preserves reverse-video style,
  works in tmux, and no longer risks killing Bubble Tea's input reader.
- **Input and palette polish landed.** Ctrl+K clears like `/clear`; tall pasted
  input and ctrl+j retain the first line; a larger input box, more reliable
  history behavior, slash palette enter handling, and theme detection/live
  cross-session theme updates round out the interaction work.
- **Local command and location controls were added.** `!command` runs a local
  shell command without a model turn, `/cd` changes the workspace directory,
  and `/pwd` reports it. Bash now respects the user's shell rather than
  assuming Bash.
- **`/report` produces a safe bug-report bundle.** It creates a prefilled
  issue link and copyable environment report with an allowlisted set of
  terminal/system details—no secrets or conversation content.
- **The status line and startup report are more informative.** They display
  workspace/model/provider/effort/spend, resource and MCP loading state, and
  update availability without becoming a startup dependency.

## CLI, integrations, release, and maintenance

- **The product was renamed from loopy to whip**, including command paths and
  documentation.
- **`whip run` became script-ready.** It gained resume, system prompt,
  max-turns, timeout, quiet/no-session, JSON event output, and piped-stdin
  support. `whip sessions` lists saved sessions, and child commands receive
  `WHIP`, `WHIP_SESSION_ID`, `WHIP_MODEL`, and `WHIP_PID` markers.
- **`whip acp` implements Agent Client Protocol v1 over stdio.** Editors such
  as Zed can create/load/list sessions, stream text, thoughts, plans, token
  updates, and tool/diff cards, cancel work, set `auto` or permission-gated
  `ask` mode, and resume the resulting sessions in the standard whip UI.
- **Updates and installation are ready for users.** A GitHub Releases pipeline
  builds Linux and macOS (x64/arm64) binaries; `install.sh` verifies checksums
  and handles authenticated private-release downloads; `whip update` reruns
  the installer. Interactive startup checks releases on a quiet 24-hour cache
  and only reports a newer version.
- **Process cleanup was hardened.** On quit or signal, whip kills and reaps
  tracked child process groups. Detached grandchildren cannot hold a command
  pipe open forever; interactive sudo/SSH commands still use a bounded PTY.
- **Permission UX was simplified.** `--cautious` makes prompts opt-in, and the
  terminal confirmation is now a direct `Proceed? [Y/n]` interaction.
- **Engineering gates became significantly stronger and faster.** CI now has
  parallelized quality jobs, race-enabled tests, lint/security/CodeQL checks,
  cross-compilation, coverage floors ratcheted to 90%, Go build caching, and
  pre-commit `golangci-lint` when installed. Dependency updates covered Go
  modules and GitHub Actions; a LICENSE and substantially expanded user and
  architecture documentation were added.

## Notable fixes included in the release window

- Correct Kimi/Moonshot tool-message naming and tool-call pairing; correct
  Kimi context windows; avoid the `max_tokens` request issue.
- Prevent MCP enable/disable races, bash timeout races, and several task-dock
  deadlock/aging/restore cases.
- Refresh stale model catalogs on launch instead of incorrectly rejecting a
  valid default model.
- Preserve session cost visibility on long paths and repair drag-to-select in
  tmux.
- Fix browser profile-launch, live-attach, and extension-relay edge cases;
  prevent native computer helper concurrency failures on newer Swift toolchains.
- Deflake the GitHub-release update test under the race detector and expand
  coverage around ACP lifecycle, MCP behavior, catalog resolution, browser
  modes, LSP, session rewind/fork, computer use, and tool streaming.
